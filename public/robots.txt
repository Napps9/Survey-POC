# See https://www.robotstxt.org/robotstxt.html for documentation on how to use the robots.txt file
#
# Every path below is reachable without signing in, and every one of them is a
# CAPABILITY: holding the URL is the whole of the authorisation. The product
# only ever hands these out deliberately, and nothing in it promises or wants
# search discoverability.
#
# robots.txt is advisory, so it is the polite half only. The binding half is the
# `X-Robots-Tag: noindex, nofollow` header the app sets on these same responses
# (ApplicationController#discourage_indexing), which a crawler ignoring this
# file still has to receive.
#
# /play/ is NOT listed, deliberately — it used to be, and that was the wrong
# tool for the job twice over:
#
#   1. It blocked link previews. A respondent passing a Verto to friends is a
#      first-class distribution channel, and Facebook/Messenger, X, LinkedIn and
#      Slack all read this file before fetching a URL to unfurl it. Disallowing
#      /play/ meant a shared Verto arrived on those platforms as a bare link
#      with no title, description or image — while WhatsApp and iMessage, which
#      build their preview on the sender's own device, showed it fine. The
#      player renders og:/twitter: tags precisely so that shared links unfurl
#      (app/views/player/show.html.erb); this line was quietly cancelling them.
#
#   2. It worked against the noindex above. A crawler that may not FETCH a URL
#      also never receives the `X-Robots-Tag` telling it not to index — so a
#      /play/ link picked up from somewhere else could still surface in results
#      as a bare URL, which is the outcome the Disallow existed to prevent.
#      Allowing the fetch is what lets the binding half actually bind.
#
# A /play/ token is still a capability and still unwanted in search; the header
# is what says so, on every response, to every crawler that reads it.
